# Blender Bonsai IFC Import Crash

Date: 2026-04-08

## Issue
Blender 5.1.0 crashes when importing IFC files generated by PyGISKit.

## Root Cause
Blender's internal function `BLI_string_split_name_number` crashes with `std::out_of_range` exception when processing IFC product names that end with underscore + non-numeric suffix.

Example problematic names:
- `NL.IMBAG.Pand.0629100000022770_roof`
- `NL.IMBAG.Pand.0629100000022770_wall`
- `NL.IMBAG.Pand.0629100000022770_floor`

The function tries to parse "roof"/"wall"/"floor" as an integer using `std::stoi()`, which throws an exception that is not properly caught.

## IFC Spec Compliance
**The names are fully IFC compliant:**
- `Name` attribute is a STRING (up to 255 chars)
- No restriction against underscores in IFC names
- This is a Blender/IfcOpenShell bug, not an IFC validation issue

## Affected Files
- `onderlegger-IFC4X3.ifc` (IFC4X3_ADD2 schema)
- `onderlegger.ifc` (IFC4 schema)

## Workarounds

### 1. Blender Version
Try a different Blender version (e.g., 4.x) that may not have this bug.

### 2. Name Modification (PyGISKit side)
Modify product naming to avoid underscore + alphabetic suffix:
- Replace `_roof` → `.roof`
- Replace `_wall` → `.wall`
- Replace `_floor` → `.floor`

This is a cosmetic workaround for Blender compatibility only.

## References
- Blender crash report: EXC_CRASH (SIGABRT) in `BLI_string_split_name_number`
- Stack trace shows `std::__1::stoi` failing on non-numeric string
